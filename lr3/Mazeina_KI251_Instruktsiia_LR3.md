# ЛР3 — запуск і скриншоти на власному комп’ютері

Проєкт: https://github.com/cikatiloa902-debug/restaurant-db
Середовище з ЛР2: MySQL 8.4 у Docker Desktop. SQL виконується клієнтом mysql у контейнері. Для ЛР3 використовуємо ту саму схему restaurant_db, але окремий Docker-проєкт restaurant-lr3 з власним томом даних. ЛР2 зберігається.

## 1. Підготовка

Запустити Docker Desktop і дочекатися готовності. На GitHub натиснути Code → Download ZIP, розпакувати. У папці restaurant-db-main мають бути docker-compose.yml, mysql, lr3. Відкрити PowerShell у цій папці.

Перевірити:
```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
[Console]::OutputEncoding = $OutputEncoding
chcp 65001
docker --version
docker compose version
```

Якщо база ЛР2 працює і займає порт 3307, спочатку зупинити її в Docker Desktop кнопкою Stop. Видаляти її або том не потрібно.

```powershell
Copy-Item .env.example .env
docker compose -p restaurant-lr3 up -d --wait
docker compose -p restaurant-lr3 ps
```
Цей запуск автоматично створює схему і початкові 35 записів ЛР2 із mysql/init. Якщо команда не виконалася, зупинитися і надіслати текст помилки — не видаляти томи.

## 2. Додаткові дані ЛР3

Виконати один раз у свіжому проєкті restaurant-lr3:
```powershell
Get-Content -Raw -Encoding UTF8 .\lr3\Mazeina_KI251_02_data_LR3.sql | docker compose -p restaurant-lr3 exec -T mysql sh -c 'exec mysql --protocol=TCP -h127.0.0.1 --default-character-set=utf8mb4 -uroot -p"$MYSQL_ROOT_PASSWORD" restaurant_db'
```

Не повторювати вставку в уже наповненій базі: первинні ключі захищають її від дублів.

## 3. Вхід у MySQL

```powershell
docker compose -p restaurant-lr3 exec mysql sh -c 'exec mysql --protocol=TCP -h127.0.0.1 --default-character-set=utf8mb4 -uroot -p"$MYSQL_ROOT_PASSWORD" restaurant_db'
```

Має з’явитися запрошення mysql>. Далі вставляти саме SQL, без команд PowerShell. Після кожного запиту має бути крапка з комою. Команда exit повертає до PowerShell.

## 4. Скриншоти для звіту

Знімати Win+Shift+S. Має бути видно SQL-команду, її результат та запрошення mysql>. Збільшити шрифт, якщо текст дрібний. Не фотографувати лише зелений статус GitHub замість результатів запиту.

1. S01 — Docker Desktop з контейнером restaurant-lr3 і MySQL 8.4. Додатково у терміналі: SELECT VERSION(), DATABASE(); та SHOW TABLES;.
2. S02 — кількість записів у 10 таблицях: перший запит із Mazeina_KI251_04_integrity_LR3.sql. Очікується 12, 12, 10, 10, 12, 15, 30, 15, 15, 10 записів відповідно до виведених назв таблиць.
3. S03 — перелік зовнішніх ключів із сумісністю типів і індексами: другий запит із файлу перевірки. Має бути 12 рядків, types_match=1 і fk_index_exists=1. Якщо не вміщується — два скриншоти.
4. S04 — SHOW INDEX FROM order_item;. Видно індекси для зовнішніх ключів.
5. Q01–Q12 — кожний із 12 запитів файлу Mazeina_KI251_03_queries_LR3.sql окремо. Копіювати від SELECT до ;. Перед запитом не потрібно вставляти SET NAMES і USE повторно. У звіт потрібні SQL і його результат для кожного запиту.

Очікувана кількість рядків Q01–Q12: 12, 10, 5, 8, 3, 15, 4, 9, 11, 12, 9, 5. Q05: стейк, салат з лососем, риба запечена. Q12: замовлення 11–15 без оплати. Q10 і Q11 навмисно відрізняються: ANY порівнює хоча б з одним напоєм, ALL — з кожним.

Надсилати скриншоти частинами: спочатку S01–S04, потім Q01–Q06 і Q07–Q12. Після цього скриншоти буде вставлено у звіт замість позначок. До цього документ є чернеткою.

## 5. Що пояснити на захисті

- dbdiagram.io — модель ЛР1. MySQL — СУБД. Docker — спосіб запуску сервера, mysql — клієнт для SQL. GitHub зберігає файли; Actions запускає незалежну перевірку.
- PRIMARY KEY однозначно визначає рядок. FOREIGN KEY пов’язує таблиці й не дозволяє посилатися на неіснуючий запис. UNIQUE(email) забороняє дубль адреси. CHECK(price>=0) забороняє від’ємну ціну.
- Індекс прискорює пошук і JOIN. У InnoDB індекси для FK створені автоматично. У нашій схемі типи всіх пар FK/PK — INT.
- SELECT обирає стовпці; FROM — таблицю; WHERE — рядки; ORDER BY — порядок; LIMIT — кількість. AS дає коротку назву або заголовок.
- JOIN з’єднує замовлення з клієнтом. LEFT JOIN зберігає позицію, коли вона містить лише food_id або лише drink_id. COALESCE повертає першу ціну, яка не NULL.
- GROUP BY збирає позиції одного замовлення. SUM рахує суму, HAVING фільтрує групи після підсумовування; WHERE фільтрує рядки до групування.
- IN — входження в набір; EXISTS — наявність пов’язаного рядка; NOT EXISTS — його відсутність; ANY — хоча б одне порівняння; ALL — усі порівняння.
- Корельований підзапит Q09 або Q12 посилається на рядок зовнішнього запиту через u.user_id або o.order_id.
- NULL означає відсутнє значення, його перевіряють IS NULL, а не = NULL.
- У навчальній схемі ЛР2 немає кількості позиції та історичної ціни. Q07 підсумовує поточні ціни меню по одному запису позиції. Реальну історичну вартість так не відновлюють. Схему навмисно не змінено в роботі про SELECT.
- `order`, `user`, `transaction` взято у зворотні лапки, щоб уникнути конфлікту ідентифікаторів зі словами SQL.

## 6. Завершення

У MySQL:
```sql
exit
```
У PowerShell:
```powershell
docker compose -p restaurant-lr3 down
```
Том з даними збережеться. Для наступного відкриття запустити up -d --wait і перейти одразу до входу в MySQL. Не виконувати дані вдруге.
