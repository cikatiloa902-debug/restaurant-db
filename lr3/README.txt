Запуск у наявному MySQL
Імпортуйте restaurant_lr3.sql у нове порожнє середовище.
Він створює окрему базу restaurant_db_lr3.
Скрипт не видаляє таблиці, але не призначений для повторної вставки
у вже заповнену базу. Попередню restaurant_db він не змінює.
Окремі скрипти запускаються у порядку 01, 02, 03, 04 з папки sql/.

Запуск у Docker
1. Відкрийте термінал у цій папці.
2. docker compose up -d --wait
3. Відкрийте будь-який клієнт MySQL: 127.0.0.1, порт 3308,
   користувач root, пароль lab3_demo_root, база restaurant_db_lr3.
4. Виконайте 03_queries.sql та 04_integrity.sql.

Запуск через GitHub Actions
У репозиторії відкрийте Actions → Restaurant LR3 MySQL check → Run workflow.
Після успішного завершення завантажте артефакт restaurant-lr3-results.
Він міститиме нові текстові результати і дамп MySQL 8.4.
SQL-файли розміщені в lr3/sql/, файл запуску — у
.github/workflows/lr3-check.yml від кореня репозиторію.

Підготовка до захисту
WHERE фільтрує рядки; HAVING — групи після агрегації.
JOIN поєднує таблиці за ключами; LEFT JOIN зберігає рядки без відповідника.
IN перевіряє входження у набір; EXISTS — наявність хоча б одного рядка.
ANY потребує хоча б одного істинного порівняння; ALL — усіх.
Корельований підзапит посилається на рядок зовнішнього запиту.
У вихідній схемі немає кількості і ціни на момент замовлення,
тому суми в Q07 розраховуються за поточними цінами меню.
